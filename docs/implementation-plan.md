# Calendar 구현 계획

작성일: 2026-10-28 (Asia/Seoul)

상태: 설계 기준 문서. 2026-10-29 초기 구현 및 검증을 진행했으며 실제 완료 범위와 제한은 [구현 현황](implementation-status.md)에 기록한다. 아래 체크리스트는 최초 계획 항목이며 전체 완료를 의미하지 않는다.

## 1. 제품 정의와 결정 상태

앱이 제공하는 이벤트를 달력에 배치하고, 날짜·이벤트·더보기 실행을 앱에 알리는 확장 가능한 WinUI 3 컨트롤을 NuGet 패키지로 제공한다.

**월간은 첫 번째 표시 방식이며, 공통 코어의 전제가 아니다.** 향후 동일한 Calendar에서 DisplayUnit을 변경하여 주간·일간을 사용할 수 있도록 설계한다.

- **확정**: 사용자와 합의한 요구사항. 구현 범위의 기준으로 사용한다.
- **설계 기본안**: 합의한 요구사항을 구체화하기 위한 제안. 구현 전 계약 검토에서 확인하며, 사용자 확정 사항으로 취급하지 않는다.
- **기술 검증**: 복원된 실제 프로젝트와 최소 실험으로 확인해야 하는 항목. 아직 검증 완료를 의미하지 않는다.

### 확정 범위

| 영역 | 첫 버전의 책임 |
| --- | --- |
| 표시 단위 | 월간 구현. 공통 설계는 향후 Week / Day 확장 고려 |
| 격자 | 요일 헤더 + 7열 + 필요한 5주/6주 자동 계산. 최소 5주. 날짜 셀 상단에 일수 표시 |

| 배치 | 종일 우선, 시간제 시작일시 오름차순, 동률이면 앱 전달 순서 |
| 상호작용 | 날짜 실행과 선택 상태 변경을 구분. 이벤트 실행은 별도 알림 |
| 공간 부족 | 마지막 표시 자리를 N개 더보기로 사용 |

| 외부 조작 | 표시 기준 날짜 등 공개 속성과 범위 정보를 제공 |
| 기본 품질 | 키보드, 포커스, UI Automation, 테마, 고대비, 크기 변경 지원 |

| 표준 기준 | RFC 5545 중 이벤트(VEVENT)에 관련된 날짜·시간·기간·발생분 의미를 준수하는 표시 계약 |

### 앱의 책임

- 연월 제목, 이전·다음·오늘 버튼 및 표시 단위 전환 UI.
- 실행 알림 이후의 Dialog / Flyout / 상세 화면 및 편집 흐름.
- 이벤트 생성·수정·삭제·저장·조회·동기화와 비동기 조회 취소.
- 반복 규칙 전개, 외부 캘린더 연동, 업무별 권한·검증.

**외부 연결은 사용하는 개발자의 앱·어댑터 책임으로 확정한다.** 이 프로젝트는 서비스 클라이언트, 인증, 동기화, CalDAV 프로토콜, 공급자 전용 어댑터나 별도 연동 패키지를 개발하지 않는다. 후속 구현 계획에도 포함하지 않는다.

패키지의 표준 기준은 RFC 5545 중 이벤트(VEVENT)의 의미와 모순되지 않는 데이터·표시 계약이다. 전체 RFC의 모든 컴포넌트나 .ics 파서·파일 입출력을 이 결정만으로 구현 범위에 추가하지 않는다. [표준 조사](calendar-interoperability-research.md)의 서비스별 내용은 배경 자료이며 구현 작업 목록이 아니다.

### 후속 범위

- 실제 주간·일간 화면과 시간축 배치.
- 이벤트 드래그 이동·기간 조절, 다중·범위 선택.
- 다른 역법, 사용자 지정 정렬 정책, 주 수 고정 옵션. 행 수는 항상 5주/6주로 자동 계산한다.
- NuGet 공개 게시 및 별도 배포 자동화. 이번 준비 작업에 게시를 포함하지 않는다.

**확정된 방향:** 최신 정식 릴리스를 개발 기준으로 사용하고, 공식 지원 중인 안정 릴리스 가운데 가장 오래된 계열까지 호환성을 검증한다. 여기서 지원은 Microsoft의 지원 기간을 뜻하며 Preview / RC / Experimental은 안정 릴리스에 포함하지 않는다.

Windows App SDK 공식 표에는 1.8의 Support level이 Maintenance로 남아 있지만 종료일은 이미 지났다. 날짜를 기준으로 지원 대상에서 제외한다. 2.0 계열의 지원이 모든 과거 2.x 패치의 지원을 뜻하지는 않는다. Microsoft 지원 조건인 최신 서비스 업데이트 적용을 전제로 한다.

**구현 기본안:**

- 개발·CI는 최신 정식 .NET SDK로 빌드한다. SDK 버전과 라이브러리 TFM은 구분한다.
- Core는 우선 net8.0, WinUI는 net8.0-windows10.0.19041.0 자산을 제공하여 .NET 8 소비 하한을 확보한다. 기존 Core의 net10.0 단독 타깃은 변경해야 한다.
- Example은 최신 정식 .NET 10을 대상으로 한다. 소비 앱은 .NET 8 / 9 / 10 각각으로 복원·빌드·실행하여 호환성을 확인한다.
- TFM 숫자마다 동일 DLL을 중복 생성하지 않는다. 최신 전용 API나 최적화가 필요할 때 net10.0 자산 등을 추가하는 멀티 타깃을 검토한다.
- net8.0 자산에서 .NET 10 전용 API를 사용하지 않는다. 최신 컴파일러 사용과 최신 런타임 API 사용은 다른 결정이다.
- Windows App SDK는 현재 2.6.4를 사용한다. 1.8 호환성과 과거 2.x 서비스 버전 호환성을 자동으로 약속하지 않는다.
- 여러 SDK 계열을 지원하게 되면 라이브러리는 선언한 최소 API 기준으로 컴파일하고 최신 환경에서도 검증한다. 최신 SDK로만 컴파일한 뒤 NuGet 의존성 하한만 낮추는 방식은 사용하지 않는다.
- 릴리스 준비 시 공식 지원 표와 최신 패치를 다시 확인하고 정확한 버전을 기록·고정한다. floating 버전으로 재현성을 잃지 않는다.
- .NET 8 / 9의 지원 종료 이후 새 릴리스의 공식 검증 하한은 .NET 10으로 재평가한다. 이미 배포한 패키지가 날짜에 따라 동작이나 TFM을 바꾸지는 않는다.
- 공식 검증 대상에서 제외하는 것과 패키지 TFM·의존성 하한을 올리는 것은 구분한다. 설치 가능성을 줄이는 변경은 호환성 파괴 변경으로 관리하고 패치에 묵시적으로 넣지 않는다.
- 설치된 SDK와 런타임, 빌드 성공, 실제 실행 성공을 별도로 확인한다. 위 표는 현재 호환성 테스트 통과를 뜻하지 않는다.

이 정책은 Windows OS 지원 하한과도 별개다. 최소 Windows 버전은 Windows App SDK와 사용하는 API의 공식 지원 조건을 함께 확인하여 확정한다.

기존 Example의 패키지 매니페스트와 실행 방식은 보존한다. NuGet 라이브러리 제작과 예제 앱의 MSIX 실행은 서로 다른 검증 항목이다.

## 4. 공통 날짜·기간 계약

### 기준 상태와 범위

- DisplayDate는 표시 기준 날짜다. 월간이라도 자동으로 해당 월의 1일로 덮어쓰지 않는다.
- SelectedDate, DisplayDate, 오늘은 독립적이다.
- PrimaryRange는 표시 방식의 대상 기간이다. 월간은 해당 월, 주간은 해당 주, 일간은 해당 날짜다.
- VisibleRange는 실제 그리는 날짜 범위다. 월간은 인접 월 날짜를 포함한 35개 또는 42개 날짜다.
- 모든 범위는 시작 포함·끝 제외로 통일하는 것을 설계 기본안으로 삼는다.
- IsOutsidePrimaryRange는 실행 대상 날짜가 PrimaryRange 밖인지 나타낸다. 월간에서는 인접 월 여부와 같다.
- 월간 밖의 계산도 가능한지 확인하기 위해 Core 테스트에서 임의의 하루·7일 범위를 입력한다. 미래 화면을 미리 구현하지 않는다.

### 이벤트 기간: 설계 기본안

- 종일: 날짜 구간 [StartDate, EndDateExclusive). 예: 28~30일은 [28일, 31일).
- 시간제 기간: 해석된 시점은 DateTimeOffset 구간 [Start, End)로 표현할 수 있다. 원본 시간대·floating 의미를 이 타입 하나로 대체하지 않는다.
- 표시 시간대는 앱이 결정하고 컨트롤에 전달한다. 기본값은 시스템 로컬 시간대 제안.
- 시간제는 선택한 표시 시간대로 투영한 후 날짜 소속을 계산한다. UTC 날짜나 offset의 날짜 부분을 그대로 셀 날짜로 사용하지 않는다.
- 종일 날짜는 시간대 변환으로 이동시키지 않는다.
- 28일 23시~29일 0시 이벤트는 28일에만 소속된다.
- 기간 이벤트의 명시 종료는 시작보다 늦어야 한다. 다만 표준에서 허용하는 종료 없는 시간제는 별도의 시점 이벤트로 연결하는 기본안을 사용한다. 실제 기간을 임의로 늘리지 않는다.
- 외부 종일 이벤트에 종료·기간이 없으면 연동 계층에서 하루로 정규화한다. DURATION이 있으면 이를 먼저 해석한다. 잘못된 명시 종료를 시점 이벤트로 바꾸어 숨기지 않는다.
- 원본의 UTC / 시간대 지정 / floating 의미와 TZID·VTIMEZONE을 연동 계층에서 유지한다. Core는 표시용 발생분을 받고, 시스템 시간대로 해석할 수 없는 정의의 해결은 연동 계층에 맡긴다.
- 시간대 투영은 순수 계산이며, 원본 시간 데이터와 저장 형식은 변경하지 않는다.
- 잘못된 구간·어댑터 실패는 입력 경계에서 원인과 대상 데이터를 식별할 수 있게 보고한다. 자동 역전·부분 적용으로 숨기지 않는다.
- 윤년, 연도 전환, 최솟값·최댓값 주변의 날짜 계산에서 overflow하지 않도록 지원 범위와 경계 동작을 P1에서 확정한다.

DateOnly는 Core 날짜 계산의 후보로 사용한다. 공개 WinUI 속성에 직접 사용할 수 있는지는 P1에서 확인하고, 필요한 경우 날짜 전달용 타입과 Core 변환 경계를 둔다. 모든 공개 날짜 속성은 동일한 규칙을 사용한다.

## 5. 앱 데이터 연결과 변경 반영

### 데이터 연결

- 앱의 모델에 특정 기반 클래스나 UI 전용 인터페이스를 강제하지 않는다.
- EventsSource와 EventAdapter로 원본 객체에서 기간·종일 여부를 읽는다.
- 빠른 시작을 위한 기본 이벤트 DTO와 기본 어댑터를 함께 제공한다.
- 제목은 배치 필수 정보가 아니다. 기본 DTO는 제목을 지원하되 사용자 지정 모델은 템플릿으로 자유롭게 표현한다.
- 기본 표시와 접근성을 위한 표시 텍스트 연결도 제공한다.
- 원본 데이터, 정규화된 이벤트 엔트리, 화면 조각을 구분한다.
- 동일한 원본 객체를 여러 엔트리로 제공하는 경우와 하나의 엔트리를 주별로 분할한 경우를 구분한다. 조각 개수로 더보기 수를 계산하지 않는다.

### RFC 5545 기준의 표시 계약과 개발자 어댑터

- 표시 입력의 단위는 개별 발생분(Occurrence)이다. 반복 시리즈 정의 → 발생분 → 화면 조각을 구분한다.
- 반복 전개와 예외·취소 적용은 사용하는 개발자의 앱·어댑터 책임이다. 컨트롤에는 표시할 발생분을 전달한다.
- UID와 RECURRENCE-ID에 대응하는 시리즈·발생분 참조를 선택적으로 연결한다. UID만으로 서로 다른 발생분을 자동 병합하지 않는다.
- 앱 모델의 상속·외부 계정 ID를 강제하지 않으면서 원본과 발생분을 실행 알림까지 유지한다.
- 공급자별 ID·계정·리소스·동기화 상태의 해석은 개발자의 어댑터에 둔다. 공통 Core에 공급자 전용 필드를 필수화하지 않는다.
- 표시에 쓰지 않는 원본 필드와 확장 속성은 앱·어댑터가 보존할 수 있도록 원본 참조를 유지한다. 컨트롤이 원본을 직렬화하거나 재작성하지 않는다.
- 공급자에 의존하지 않는 RFC 5545 의미의 합성 데이터와 일반 어댑터 예제로 검증한다. 실제 서비스 계정·네트워크 연결 테스트는 이 프로젝트의 인수 조건이 아니다.
- 공개 문서에는 VEVENT의 지원 의미·제약과 검증 범위를 명시한다. UI만으로 RFC 5545 전체 구현을 주장하지 않는다.

표준 준수와 외부 연결 제외는 확정된 범위다. 구체적인 메타데이터 타입과 시점 표시 정책은 P1에서 확정한다. [조사 문서](calendar-interoperability-research.md)는 범위 결정의 배경 자료로 유지한다.

### 변경 반영

- 컬렉션의 Add / Remove / Replace / Move / Reset을 반영한다.
- 앱 전달 순서의 동률 해소 기준은 현재 컬렉션의 순서다. Move도 정렬에 영향을 준다.
- INotifyPropertyChanged를 제공하는 원본은 알림을 받으면 어댑터 정보를 재평가한다.
- 변경 알림이 없는 모델을 위한 명시적 RefreshEvents 진입점을 제공한다.
- 소스·어댑터 교체, Unloaded, 다시 Loaded 시 구독을 해제·복구한다. 중복 구독과 해제 후 참조 유지를 검증한다.
- 컬렉션 변경은 UI 스레드 계약으로 명시한다. 내부에서 비동기 데이터 조회를 시작하지 않는다.
- 빠른 범위 변경 이후 오래된 조회 결과가 도착하는 문제는 앱이 요청 취소·범위 비교로 처리한다.

## 6. 공개 API 초안

아래는 동작 계약의 초안이다. 정확한 CLR 타입, DependencyProperty 구성, WinRT 노출 여부는 P1에서 검증한다. WPF의 속성 등록·읽기 전용 DP 방식을 그대로 가져오지 않는다.

| 속성·진입점 | 의미 |
| --- | --- |
| DisplayUnit | 첫 버전은 Month. 향후 Week / Day 확장 |
| DisplayDate | 외부에서 읽고 변경하는 표시 기준 날짜 |
| SelectedDate | 선택된 날짜. 미선택 허용 |
| SelectionMode | 날짜 선택 None / Single. 기본 Single(ON) |
| IsEventSelectionEnabled | 이벤트 선택 상태 유지 허용 여부. 기본 true(ON) |
| IsEventInvocationEnabled | 이벤트 실행 알림 허용 여부. 기본 true(ON), 선택과 독립 |
| SelectedEvent | 현재 선택된 발생분. null로 해제. 포커스와 독립적으로 유지 |
| FirstDayOfWeek | 언어·지역 설정을 초기값으로 사용, 앱에서 변경 가능 |
| DisplayTimeZone | 시간제 이벤트를 날짜와 화면 시간으로 투영하는 기준. 설계 기본안 |
| EventsSource / EventAdapter | 원본 컬렉션과 기간 정보 연결 |
| EventTemplate | 원본 데이터와 표시 조각 정보를 사용한 사용자 지정 |
| DateHeaderTemplate / DayOfWeekHeaderTemplate | 일수 영역 / 요일 헤더 사용자 지정 |
| MonthOptions | MonthViewOptions 객체. 월간 이벤트 행 높이·날짜 헤더 높이·5주/6주 정책 |
| PrimaryRange / VisibleRange | 읽기 전용 범위 스냅샷 |
| RefreshEvents() | 변경 알림이 없는 원본의 재평가 |

- 첫 버전에는 실제 동작하는 Month만 공개한다. 미구현 Week / Day 값을 정상 동작처럼 받아들이지 않는다.
- 공통 속성에 월간 전용 레인·6주·인접 월 설정을 섞지 않는다.
- 바인딩으로 DisplayDate / SelectedDate를 읽고 갱신할 수 있어야 한다. WinUI의 바인딩 모드를 검증하고 예제에서 명시한다.
- 기본 이벤트 템플릿과 의미별 테마 리소스를 제공한다.
- 날짜 셀 전체 교체는 첫 버전의 필수 API로 두지 않는다. 입력·접근성 계약을 유지할 수 있는 확장부터 제공한다.

### 상호작용 알림

| 알림 | 전달 데이터·발생 조건 |
| --- | --- |
| DateInvoked | 실행 날짜, IsOutsidePrimaryRange. 같은 날짜 재실행에도 발생 |
| SelectedDateChanged | 이전·이후 선택 날짜. 실제 값이 바뀐 경우만 발생 |
| SelectedEventChanged | 이전·이후 선택 발생분. 실제 선택이 바뀐 경우만 발생 |
| EventInvoked | 원본 이벤트 및 실행한 발생분 참조·기간, 실행 날짜, IsOutsidePrimaryRange |
| MoreInvoked | 해당 날짜, 정렬된 전체 발생분 목록과 원본 연결, IsOutsidePrimaryRange |
| VisibleRangeChanged | 이전·이후 대상 기간과 실제 표시 기간 |

- DateInvoked / EventInvoked / MoreInvoked는 기본 Dialog / Flyout을 열지 않는다.
- 이벤트·더보기 실행은 DateInvoked로 중복 전달하지 않으며, 날짜 선택도 자동 변경하지 않는 안을 사용한다.
- 일반 날짜 실행 시 Single 모드라면 선택을 먼저 갱신하고 DateInvoked를 전달한다.
- 날짜 선택과 이벤트 선택 정책은 독립적이며 기본 ON이다. 이벤트 선택이 OFF면 이벤트 버튼과 내부 입력 컨트롤의 포인터·키보드 실행 및 EventInvoked를 차단한다. 더보기는 계속 사용할 수 있다.
- 이벤트 선택은 포커스와 독립적인 2 DIP 외곽선으로 표시하며 같은 발생분의 모든 표시 조각에 적용한다. 호버·누름에서도 이벤트용 배경·글자색 정책을 유지한다. 툴팁은 기본 제공하지 않는다.
- SelectedDate를 코드에서 바꾸면 선택 변경만 알린다. DateInvoked를 합성하지 않는다.
- 인접 월 날짜 실행으로 DisplayDate를 자동 변경하지 않는다.
- MoreInvoked는 숨겨진 이벤트만이 아닌 해당 날짜 전체 이벤트의 실행 시점 스냅샷을 전달한다.
- 반복 회차별 데이터가 전달되어도 원본을 되찾을 수 있어야 한다. 같은 발생분을 나눈 화면 조각을 서로 다른 이벤트로 돌려주지 않는다.
- 월 변경·리사이즈가 이벤트 원본이나 선택 상태를 임의로 수정하지 않는다.
- 기간 막대의 포인터 실행은 실제 눌린 날짜 열을 전달한다. 키보드 실행은 해당 조각의 현재 포커스 날짜, 없으면 조각의 첫 표시 날짜를 사용한다.
- 앱이 팝업 위치를 잡을 수 있는 앵커·좌표 정보는 WinUI 알림 인자에서 검토한다. Core에는 UI 참조를 넣지 않는다.

## 7. 월간 배치 알고리즘

### 7.1 격자

1. DisplayDate가 속한 월로 PrimaryRange를 구한다.
2. FirstDayOfWeek 기준으로 첫 주 시작을 계산한다.
3. 월의 시작 요일 오프셋과 일수를 합쳐 필요한 주 수를 계산하고 최소 5주로 올린다. 항상 35/42개 날짜로 VisibleRange를 구성한다.
4. 각 날짜에 IsToday, IsSelected, IsOutsidePrimaryRange를 부여한다.
5. 요일 헤더와 셀의 시작 요일이 항상 일치하도록 한다.

첫 버전의 달력 체계는 그레고리력이다. 지역화는 요일명·텍스트·주 시작 설정에 적용하고 역법 지원과 구분한다.

### 7.2 범위 투영과 원본 연결

1. VisibleRange와 교차하는 기간 이벤트를 선택한다. 시작일이 범위 밖이어도 종료가 범위 안에 있으면 포함한다. 시점 이벤트는 시작 포함·끝 제외 범위에 시점이 속하는지 별도로 판정한다.
2. 원본 기간을 보존한 채 실제 표시 구간을 자른다.
3. 시간제 이벤트는 표시 시간대로 투영하여 소속 날짜를 구한다. 시점 이벤트는 해당 날짜 한 셀에 연결하며 표현을 위해 원본 기간을 늘리지 않는다.
4. 주 경계에서 시각적 조각으로 나눈다. 월 경계만으로는 나누지 않는다.
5. 조각은 원본 엔트리, 표시 시작·끝, 이전·이후 이어짐 정보를 가진다.
6. 인접 월 경계를 가로지르는 하나의 막대에서도 실행 날짜에 따라 boolean이 달라진다.

### 7.3 정렬과 레인

- 공통 기본 정렬: 종일 먼저 → 시간제 발생분의 실제 시작일시(표시 범위로 자르기 전) 오름차순 → 소스 인덱스. 반복 회차의 원래 시작 식별값은 실제 이동된 시작 시각과 구분한다.
- 종일끼리는 소스 순서다. 기간 길이 우선, 제목순 등 별도 규칙을 추가하지 않는다.
- 주별로 정렬 순서와 날짜 겹침을 고려하여 수평 레인에 배치한다.
- 같은 주의 하나의 조각은 날짜마다 레인을 바꾸지 않는다.
- 같은 날짜에서 겹치는 이벤트는 정렬상 앞선 이벤트가 위에 있어야 한다.
- 단순한 빈 레인 우선 채우기로 후순위 이벤트가 선순위 위에 올라가는 것을 허용하지 않는다.
- 구현 기본안은 정렬 순서대로 처리하면서, 먼저 배치된 겹치는 조각보다 아래인 가장 낮은 레인을 선택하는 방식이다. 겹치지 않는 조각은 같은 레인을 공유할 수 있다.
- 위 규칙으로 생기는 빈 공간은 정렬·연결성보다 우선하여 채우지 않는다. 밀도보다 동작의 예측 가능성을 우선한다.
- 다음 주에서는 새로 배치한다. 주 사이의 레인 높이는 동일할 필요가 없다.

### 7.4 넘침과 N개 더보기

1. UI 측정값으로 각 주에서 사용할 수 있는 이벤트 행 수를 구한다. Core는 픽셀 대신 행 용량을 받는다.
2. 모든 조각이 들어가면 더보기 공간을 예약하지 않는다.
3. 한 날짜라도 넘치면 그 주의 마지막 행을 더보기 전용으로 예약하여 공통 표시 용량을 정한다.
4. 표시 용량 밖의 조각은 해당 주 전체에서 숨긴다. 같은 조각을 날짜 중간에서만 숨기지 않는다.
5. 날짜별 전체 이벤트 수와 실제 표시 이벤트 수의 차이를 숨김 수 N으로 계산한다.
6. N > 0인 날짜에만 더보기를 표시한다. 다른 날짜는 예약된 마지막 행이 비어 있을 수 있다.
7. 조각과 무관하게 원본 엔트리 하나는 날짜별로 한 번만 집계한다.

**설계 기본안:** 월간 이벤트 행은 동일 높이로 사용하고 MonthViewOptions에서 높이·간격을 조정한다. 사용자 지정 템플릿도 그 행 안에서 렌더링한다. 임의 높이 템플릿을 자동으로 섞는 기능은 첫 버전 범위가 아니다.

이벤트 영역이 한 행이면 더보기만 표시할 수 있다. 날짜 헤더와 더보기 한 행을 담을 수 있는 최소 크기를 측정·문서화한다. 그보다 작은 공간에서도 음수 크기, 날짜 영역 침범, 잘못된 더보기 개수를 만들지 않는다.

## 8. WinUI 표현과 입력

- Calendar는 기본 스타일을 제공하는 템플릿 컨트롤로 구현하는 안을 사용한다.
- 날짜 바탕·헤더와 주별 이벤트 오버레이를 분리하여 기간 막대를 셀 경계에 걸쳐 그린다.
- 컨트롤에 연월 제목·탐색 도구 모음·자동 실행 팝업을 넣지 않는다.
- 이벤트 템플릿 안의 Button 등 독립 입력은 부모 이벤트·날짜 실행으로 중복 전달하지 않는다.
- 마우스·터치·키보드의 실행 의미를 통일한다. 더블 클릭 전용 편집 규칙은 추가하지 않는다.
- 날짜 방향키는 현재 SelectedDate를 기준으로 좌우 하루·상하 일주일씩 즉시 선택하고 SelectedDateChanged를 알린다. 미선택이면 입력을 받은 셀이 기준이다. 포커스만 이동하는 중간 상태와 별도 날짜 포커스 테두리는 제공하지 않는다. 선택 OFF에서는 방향키 선택도 중지한다. 보이는 인접 월까지 이동할 수 있으나 표시 범위 밖 자동 탐색은 하지 않는다.
- Enter / Space로 실행하고, 키보드로 이벤트와 더보기에도 접근할 수 있게 한다. 날짜 셀 전체를 불필요하게 긴 Tab 순서로 만들지 않도록 포커스 모델을 P1에서 검토한다.
- 오늘·선택·포커스를 구분해서 표현한다. 기본·hover·pressed·disabled 상태도 정의한다.
- Light / Dark / HighContrast 및 의미별 테마 리소스를 제공한다.
- UI Automation은 날짜 전체 이름, 이벤트 설명·기간·실행, 더보기 날짜·숨김 수를 전달한다. 여러 주에 나뉜 조각도 원본 연결과 접근 가능한 이름을 유지한다.
- 지역화된 요일명과 더보기 문자열을 제공한다. 기본 언어 및 fallback 범위를 README에 명시한다.
- 오늘 강조는 날짜 전환과 앱 재활성화 시 갱신하되 DisplayDate는 이동시키지 않는다.
- 리사이즈·데이터 변경 시 재계산을 합치고, 숨겨진 이벤트의 불필요한 시각 요소를 만들지 않는다.

완료 조건: 모든 프로젝트가 의도대로 빌드되고, 예제 앱의 실제 활성화를 확인한다. 명령 시작이나 빌드 성공을 실행 확인으로 대신하지 않는다.

| 한 행만 사용 가능 | 필요하면 더보기만 표시, 전체 수 정확 |
| 전체 범위보다 일찍 시작·늦게 끝나는 이벤트 | 표시 범위로 자르되 원본 기간 보존 |
| 자정 종료·시간대가 다른 시간제·DST 경계 | 표시 날짜와 원본 구간의 의미 보존 |

| 같은 날짜 재실행 | DateInvoked 재발생, 선택 변경 알림 중복 없음 |
| 이벤트 / 더보기 / 템플릿 내부 버튼 실행 | 날짜 실행이나 불필요한 부모 실행 중복 없음 |

핵심 계산은 단위 테스트, 입력·포커스·알림·시각 자원은 실제 WinUI 앱으로 검증한다. 구조를 그대로 따라 하는 테스트보다 경계·겹침·정렬·숨김 수·원본 연결을 검증한다.

## 11. 구현 착수 시 검토할 설계 기본안

사용자 확정 요구와 혼동하지 않도록 다음 항목을 별도 기록한다. P0 / P1에서 확정 후 본문에 반영한다.

| 항목 | 현재 기본안 |
| --- | --- |
| TFM 자산 구성 | 정책은 최신 개발 / 가장 오래된 공식 지원 계열까지 호환으로 확정. 자산은 net8.0 하한 우선, 필요 시 최신 전용 타깃 추가 |
| 기간 의미 | 기간은 시작 포함·끝 제외 및 종료 > 시작. 표준의 종료 없는 이벤트는 별도 하루 / 시점 정규화 |
| 시간대 | 앱 지정 표시 시간대, 미지정 시 시스템 로컬. 원본 시간대·floating 의미는 별도 보존 |
| 월간 배치 | 종일·시간제를 같은 영역에서 기간 막대로 표현 |
| 빈 레인 | 연결성·정렬 준수 우선, 최대 밀도는 목표 아님 |
| 넘침 | 주 단위 마지막 행 예약, 조각 전체 표시/숨김 |
| 템플릿 높이 | 월간에서는 설정 가능한 동일 행 높이 |
| 선택·입력 | 기본 Single, 방향키는 즉시 날짜 선택·변경 알림, 클릭·Enter·Space로 실행 알림 |
| 공개 날짜 타입 | Core DateOnly 후보, WinUI 바인딩·투영 검증 후 결정 |
| 패키지 구성 | Core / WinUI 프로젝트 분리, Byungmeo.Calendar.WinUI 단일 패키지에 두 DLL 동봉 |

주간·일간 화면과 외부 확장 플러그인 API를 지금 구현하지 않는다. 공통 코어가 월간을 전제하지 않는지, 향후 다른 배치 방식이 같은 입력을 사용할 수 있는지를 검증한다.
